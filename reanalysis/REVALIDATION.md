# 고객 만족도 예측 모델 개선 및 재검증
**분석일: 2026.09.07**

4월에 진행한 고객 만족도 예측 프로젝트를 바탕으로, 모델 평가 방식과 전처리 파이프라인을 보완했습니다. 정확도뿐 아니라 중립·불만족 고객의 예측 성능을 함께 확인하고, 팀 공통 모델의 추가 학습 결과를 비교했습니다.

이번 분석에서는 다음 세 가지에 집중했습니다.

- 모델별 예측값과 평가 결과의 일관성 확보
- 학습·검증·테스트 데이터의 역할 분리
- 클래스별 성능과 변수 중요도를 활용한 결과 해석

## 1. 평가 과정 개선

| 개선 항목 | 적용 내용 | 확인 방법 |
|---|---|---|
| 모델별 예측값 관리 | 평가할 때마다 해당 모델의 예측을 새로 계산하도록 공통 함수 구성 | 서로 다른 예측을 내는 두 모델로 평가 결과 확인 |
| 전처리 일관성 | 학습 단계에서 정한 결측치 처리·범주 매핑·스케일링 규칙 재사용 | 같은 데이터를 단일 행과 배치로 변환했을 때 결과 비교 |
| 데이터 누수 방지 | 설문 데이터를 먼저 분할하고 학습 데이터에만 전처리 학습 | 전처리 코드와 데이터 분할 기록 확인 |
| 추가 학습 실험 분리 | 실험마다 같은 초기 checkpoint를 다시 불러와 학습 | 독립적인 모델 객체로 실험 수행 |
| 모델 선택 기준 | validation macro F1으로 선택하고 test로 최종 평가 | 선택 기준·표본 수·성능 지표 저장 |

전처리와 평가 동작을 확인하는 자동 테스트 6개를 통과했습니다. 분류 임계값은 모든 관련 실험에서 0.5로 고정했습니다.

## 2. 머신러닝·딥러닝 모델 비교

### 데이터와 평가 설계

설문 데이터 19,278건의 응답 분포는 다음과 같습니다.

| 클래스 | 응답 수 | 비율 |
|---|---:|---:|
| 만족 | 17,293건 | 약 89.7% |
| 중립 또는 불만족 | 1,985건 | 약 10.3% |

만족 응답이 대부분이므로 정확도만으로는 중립·불만족 고객을 얼마나 잘 구분하는지 파악하기 어렵습니다. 이에 두 클래스를 균형 있게 평가하는 **macro F1**과 **중립·불만족 recall**을 함께 사용했습니다.

데이터는 클래스 비율을 유지해 다음과 같이 분할했습니다.

| 구분 | 표본 수 | 용도 |
|---|---:|---|
| Train | 11,566건 | 전처리 학습과 모델 학습 |
| Validation | 3,856건 | 모델 비교와 선택 |
| Test | 3,856건 | 선택 이후 성능 평가 |

분할 seed는 42입니다. 결측치 처리, 범주형 인코딩, MinMaxScaler는 학습 데이터로만 학습했으며, 변환 후 입력 변수는 83개입니다.

### 비교 모델과 선택 기준

Random Forest, 단층 sigmoid 모델, 은닉층 DNN, Dropout DNN, EarlyStopping DNN, 공유 모델 구조 재구성 모델을 비교했습니다.

**Validation macro F1이 가장 높은 모델을 선택하고, 동률이면 중립·불만족 recall을 기준으로 판단했습니다.**

### 주요 결과

선택된 Random Forest의 test 성능은 다음과 같습니다.

| Accuracy | Macro F1 | 중립·불만족 Recall | 평가 표본 |
|---:|---:|---:|---:|
| **96.94%** | **0.908** | **74.31%** | 3,856건 |

혼동행렬은 다음과 같습니다.

| 실제 클래스 / 예측 클래스 | 중립·불만족 | 만족 |
|---|---:|---:|
| 중립·불만족 | 295 | 102 |
| 만족 | 16 | 3,443 |

![혼동행렬](https://raw.githubusercontent.com/cascademon/project_01/main/reanalysis/assets/confusion-matrix.png)

전체 정확도는 높았지만 중립·불만족 고객 397건 중 102건을 만족으로 예측했습니다. 이 결과를 바탕으로 **중립·불만족 고객의 오분류 사례 분석**을 다음 개선 과제로 정리했습니다.

전체 모델 비교에서는 EarlyStopping DNN의 test macro F1이 0.913으로 나타났습니다. 최종 모델은 사전에 정한 validation 기준에 따라 Random Forest로 유지했습니다.

83개 입력으로 새로 학습한 공유 구조 보조 모델에서는 중립·불만족 recall이 0으로 나타나, 만족 클래스로 예측이 쏠리는 현상을 확인했습니다. 이 실험도 전체 비교표에 포함했습니다.

## 3. 팀 공통 저장 모델의 추가 학습

### 모델과 전처리 구성

저장된 모델을 기준으로 다음 네 가지 방법을 비교했습니다.

1. 추가 학습 전 성능 평가
2. 같은 구조의 모델을 새로 학습
3. 전체 층 추가 학습
4. 일부 층 미세 조정

저장 모델의 구조는 입력 78개, 은닉층 64–32–16–8–4, Dropout 0.3입니다. 저장소의 두 `.keras` 파일은 해시가 동일했습니다.

입력 컬럼의 이름과 순서를 고정하고 기존 코드의 결측치 처리·인코딩 규칙을 적용했습니다. 저장된 scaler의 주요 값과 재구성한 scaler의 값이 일치하는 것을 확인한 뒤 실행 환경에 맞춰 사용했습니다.

### 실험 조건

추가 학습 데이터 850건을 train 680건과 validation 170건으로 계층 분할하고, 별도 350건으로 평가했습니다.

각 실험은 동일한 초기 checkpoint에서 시작했으며, 모델 선택에는 validation macro F1을 사용했습니다. 설문·추가 학습·추가 평가 데이터 사이의 고객 ID 중복은 없었습니다.

### 결과 비교

| 실험 | Validation Macro F1 | Test Accuracy | Test Macro F1 | 중립·불만족 Recall |
|---|---:|---:|---:|---:|
| 추가 학습 전 | 0.923 | 90.57% | 0.906 | 83.25% |
| 같은 구조 신규 학습 | 0.928 | 88.29% | 0.882 | 90.58% |
| **전체 층 추가 학습 — 선택 모델** | **0.953** | **91.71%** | **0.917** | **91.10%** |
| 일부 층 미세 조정 | 0.935 | 92.29% | 0.923 | 88.48% |

Validation macro F1이 가장 높은 **전체 층 추가 학습 모델**을 선택했습니다.

같은 평가 표본에서 추가 학습 전과 비교하면:

- Accuracy: **90.57% → 91.71%**, 약 **1.14%p 상승**
- 중립·불만족 recall: **83.25% → 91.10%**, 약 **7.85%p 상승**

일부 층 미세 조정은 test 정확도가 더 높았지만, 전체 층 추가 학습은 validation macro F1과 test의 중립·불만족 recall에서 더 높은 결과를 보였습니다.

## 4. 주요 예측 요인과 서비스 개선 방향

Random Forest의 검증 데이터에서 permutation importance를 계산했습니다. 변수를 섞었을 때 macro F1이 얼마나 감소하는지 5회 반복 측정했습니다.

| 주요 변수 | Macro F1 평균 감소량 | 분석에서의 활용 |
|---|---:|---|
| 여행 목적 | 0.182 | 출장·개인 여행 고객을 구분한 집단별 분석 |
| 기내 Wi-Fi | 0.152 | 접속과 품질 관련 불편 조사 |
| 온라인 탑승 | 0.063 | 탑승 절차·안내 과정의 불편 조사 |

![변수 중요도](https://raw.githubusercontent.com/cascademon/project_01/main/reanalysis/assets/feature-importance.png)

여행 목적은 고객 세분화 기준으로 활용하고, Wi-Fi와 온라인 탑승은 서비스 경험을 추가로 조사할 항목으로 정리했습니다.

이후 고객 의견과 운영 데이터를 함께 검토해 불편의 원인을 구체화하고, 개선안의 우선순위를 판단하는 방향을 제안합니다.

## 5. 한계와 향후 개선

### 평가의 안정성

현재 결과는 단일 seed·단일 분할에서 측정했습니다. 여러 seed와 교차검증으로 성능 변동을 확인할 필요가 있습니다.

추가 평가 350건은 기존 프로젝트에서 사용한 데이터이므로, 독립적인 신규 데이터 평가를 통해 일반화 성능을 확인하는 것이 다음 과제입니다. 현재 표본에서 나타난 성능 변화의 통계적 유의성은 별도로 검증하지 않았습니다.

### 저장 모델의 재현성

저장된 모델의 전체 학습 이력과 일부 전처리 객체가 남아 있지 않아 기존 코드와 데이터로 전처리를 복원했습니다. 저장 모델이 당시 발표에 사용된 checkpoint와 같은 버전인지도 확인되지 않았습니다.

향후에는 모델과 함께 전처리 객체, 데이터 버전, 학습 설정, 실행 결과를 묶어 저장할 필요가 있습니다.

### 실험별 비교 범위

기본 모델 비교는 83개 입력과 설문 분할 데이터를, 저장 모델 추가 학습은 78개 입력과 별도 데이터를 사용했습니다. 두 실험은 각각의 조건 안에서 비교합니다.

4월 팀 보고서와 9월 재검증은 별도의 실험 기록으로 관리합니다. 보고서 수치와 저장 모델 실행 결과의 상세 차이는 [실험 이력 대조 기록](https://github.com/cascademon/project_01/blob/main/reanalysis/SOURCE_COMPARISON.md)에 정리했습니다.

### 서비스 적용

변수 중요도는 예측에 기여하는 정도이며 서비스 개선의 인과효과는 아닙니다. 개선안의 실제 도입 효과는 측정하지 않았으며, 고객 의견 조사와 별도의 효과 검증이 필요합니다.

## 6. 회고

이번 후속 분석에서는 모델의 정확도를 비교하는 것에서 나아가, 전처리와 평가 과정이 일관되게 작동하는지 점검했습니다.

특히 높은 정확도에서도 중립·불만족 고객을 놓치는 사례가 있다는 점을 확인하면서, 프로젝트의 목적에 맞는 평가 지표를 함께 살펴보는 것이 중요하다는 점을 배웠습니다.

다음 단계에서는 중립·불만족 오분류 사례를 분석하고, 여러 데이터 분할과 신규 표본에서 성능을 검증하는 방향으로 발전시키고자 합니다.

## 부록. 실행 환경과 재실행 방법

Python 3.12, CPU 환경에서 실행했습니다. 세부 패키지 버전은 `requirements-lock.txt`, 데이터 해시와 모델 설정은 `reanalysis/results/results.json`에서 확인할 수 있습니다.

```bash
python -m pip install -r requirements-lock.txt
python -m pytest -q
python -m reanalysis.pipeline
python -m reanalysis.legacy_shared
python -m reanalysis.publish_results
```

- 고객 ID가 포함된 `split_ids.csv`는 로컬 분할 확인용으로 사용하며 공개 저장소에서는 제외했습니다. 실행 시 같은 seed와 분할 규칙으로 생성됩니다.
- `python -m reanalysis.pipeline --smoke --output reanalysis/smoke-results`는 2 epochs 실행 점검용입니다.
- 학습 산출물은 `reanalysis/artifacts/`에 저장해 기존 저장 모델과 분리합니다.
- 저장 scaler의 scikit-learn 버전은 1.6.1, 재검증 환경은 1.7.2입니다. 주요 변환 값의 일치를 확인한 뒤 재구성한 scaler를 사용했습니다.
- 실행 중 TensorFlow 호환성·retracing 경고가 발생했으나 전체 실행은 종료 코드 0으로 완료됐습니다.
